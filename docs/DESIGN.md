# Adventure Station design direction

The original logo and tool characters are the brand, not a sticker on a general dashboard. The public site is an invitation to make something; the studio desk is a place to get work done.

## Direction

- Studio blue `#155e75` leads navigation and primary operations; ink `#173844` carries text. Brush red `#b63e35` is a purposeful public action color, sunflower `#f2c14d` a small supporting accent. White and cool paper `#f3f7f8` keep the desk calm. Status meaning always includes words.
- Trebuchet MS with local system fallbacks carries friendly, rounded display type; operational text uses a highly legible system sans stack. Compact, bold admin headings replace the oversized editorial serif. Numeric information uses tabular figures. No remote fonts or third-party scripts.
- A short, aligned color strip refers to the colors on the tools in the existing artwork. The artwork itself is the expressive feature on the public homepage. Remove the arbitrary spark, italic single-word headline and decorative labels. Do not spread ornament through the desk.
- Group staff navigation by daily work, website and business. A deliberate mobile menu replaces the long horizontal strip of links. Common actions stay near their records.
- Setup is a prioritized work list with one next action, compact task rows, an honest readiness summary and expandable forms. It is not seven interchangeable cards. Developer checks are visibly separate from owner decisions.
- Public workshop choices emphasize activity, ages, next date, venue, price and actual availability. Empty states explain what to do next. Synthetic preview activities remain explicitly labeled.
- Mobile inputs stay at least 16px and controls at least 44px high. Registration tables become labeled record summaries at narrow widths. Visible focus, reduced motion, safe-area padding, keyboard use and native disclosure are baseline requirements. Zoom remains enabled.

The first pass rejects beige/serif/card-grid defaults. The second pass must inspect actual desktop/mobile screens, realistic long synthetic content, validation and empty states before accepting the result. Preserve every operating and privacy gate.

## Rendered review

The desktop comparison shows a smaller operational heading, clearer navigation groups and a work list with a single next action. Native disclosures keep occasional Setup decisions out of the main scanning path; hash links reveal and focus the relevant form. Overview now puts upcoming classes and follow-up before period-based financial reporting. Messages use a readable list, and narrow registration tables become labeled records.

The public site keeps the original tool characters, with a restrained blue frame, brush-red action and short material-color strip. Workshop summaries expose age, duration, date, venue, price and available places before navigation. A visual review caught artwork extending into card text; explicit image containment corrected it. The same original artwork remains the honest fallback until the owner supplies permitted activity images. No artificial customer photographs or business claims were created.

Actual viewport checks cover 320, 360, 390, 768, 1024, 1440 and 1920 pixels. Long text, native required-field validation, keyboard menus/Escape/focus, reduced motion, 200% text and CSS page scaling were checked. This is not a native-device or full browser-zoom certification. Targeted axe checks complement the visual review; they do not establish full WCAG conformance. The hosted public homepage and closed-registration journey were inspected in a browser. Hosted staff review still requires the owner's Access sign-in.

Before/after Setup and public-home screenshots, mobile captures and the hosted homepage are retained locally under ignored `local-artifacts/design-review/`. They are synthetic development evidence, not photographs of customers. The local comparison gallery preserves the original captures alongside the result.
